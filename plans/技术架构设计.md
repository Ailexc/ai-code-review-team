# 多Agent协作代码审查系统 - 技术架构设计

## 1. 项目概述

### 1.1 项目定位
构建一个**多 Agent 协作代码审查系统**，模拟真实 Code Review 流程。用户提交代码（PR / 本地目录 / 代码粘贴等），系统触发多个专业 Agent 并行审查，由主 Agent 汇总生成结构化审查报告。核心场景是 **PR/diff 增量审查**，同时保留本地项目管理能力作为审查对象的统一入口。

### 1.2 核心价值
- **多 Agent 协作**：主 Agent 调度多个专业 Agent 并行审查，上下文隔离、结果聚合
- **多维审查**：围绕安全 / 规范 / 依赖 / 测试覆盖等**可验证维度**审查，确定性工具兜底 + LLM 语义补充
- **智能分析**：LLM 驱动的深度分析，超越传统静态检查
- **增量审查**：优先审查变更代码，控制 token 成本

### 1.3 目标用户
- 个人开发者：管理自己的多个项目 / PR
- 技术团队：团队代码质量审查
- 学习者：多 Agent 协作、任务编排、工具集成的最佳实践项目

### 4.2 详细数据模型

#### 4.2.1 项目表 (projects)

```sql
CREATE TABLE projects (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    path VARCHAR(1024) NOT NULL UNIQUE,
    description TEXT,
    language VARCHAR(50),
    framework VARCHAR(50),
    git_remote VARCHAR(512),
    health_score DECIMAL(5,2) DEFAULT 0.00,
    last_review_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    is_active BOOLEAN DEFAULT TRUE,
    
    INDEX idx_projects_name (name),
    INDEX idx_projects_language (language),
    INDEX idx_projects_health_score (health_score)
);
```

#### 4.2.2 审查记录表 (reviews)

```sql
CREATE TABLE reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    trigger_type VARCHAR(50) NOT NULL, -- manual, scheduled, webhook
    status VARCHAR(50) NOT NULL, -- pending, running, completed, failed
    review_type VARCHAR(100) NOT NULL, -- full, security, code_style, dependency, test_coverage, etc.
    started_at TIMESTAMP WITH TIME ZONE,
    completed_at TIMESTAMP WITH TIME ZONE,
    duration_seconds INTEGER,
    health_score_snapshot DECIMAL(5,2), -- 该次审查时的健康度快照，用于趋势还原
    total_findings INTEGER DEFAULT 0,
    critical_count INTEGER DEFAULT 0,
    warning_count INTEGER DEFAULT 0,
    suggestion_count INTEGER DEFAULT 0,
    nitpick_count INTEGER DEFAULT 0,
    summary TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_reviews_project_id (project_id),
    INDEX idx_reviews_status (status),
    INDEX idx_reviews_created_at (created_at)
);
```

#### 4.2.3 审查发现表 (findings)

```sql
CREATE TABLE findings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    review_id UUID NOT NULL REFERENCES reviews(id) ON DELETE CASCADE,
    agent_name VARCHAR(100) NOT NULL,
    category VARCHAR(100) NOT NULL, -- security, code_style, dependency, test_coverage, performance, git
    severity VARCHAR(50) NOT NULL, -- critical, warning, suggestion, nitpick
    status VARCHAR(20) NOT NULL DEFAULT 'open', -- open, acknowledged, fixed
    file_path VARCHAR(1024),
    line_number INTEGER,
    column_number INTEGER,
    code_snippet TEXT,
    message TEXT NOT NULL,
    description TEXT,
    suggestion TEXT,
    reference_url VARCHAR(512),
    is_auto_fixable BOOLEAN DEFAULT FALSE,
    fix_suggestion TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_findings_review_id (review_id),
    INDEX idx_findings_severity (severity),
    INDEX idx_findings_category (category),
    INDEX idx_findings_agent_name (agent_name),
    INDEX idx_findings_status (status)
);
```

> **说明**：`status` 字段对应前端"已解决"统计与 `PUT /findings/{id}/status` 接口，避免文档与 API 自相矛盾。

#### 4.2.4 项目配置表 (project_configs)

```sql
CREATE TABLE project_configs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    config_key VARCHAR(255) NOT NULL,
    config_value JSONB NOT NULL,
    description TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    UNIQUE(project_id, config_key),
    INDEX idx_project_configs_project_id (project_id)
);
```

#### 4.2.5 审查规则表 (review_rules)

```sql
CREATE TABLE review_rules (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    agent_name VARCHAR(100) NOT NULL,
    rule_name VARCHAR(255) NOT NULL,
    rule_type VARCHAR(50) NOT NULL, -- semgrep, custom, llm
    rule_config JSONB NOT NULL,
    severity VARCHAR(50) NOT NULL,
    is_enabled BOOLEAN DEFAULT TRUE,
    description TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_review_rules_agent_name (agent_name),
    INDEX idx_review_rules_rule_type (rule_type)
);
```

#### 4.2.6 审查历史趋势（不单独建表）

趋势数据（健康度、问题数随时间变化）**由 `reviews` 表按时间派生**，不单独建 `review_trends` 快照表——避免冗余与数据一致性问题。查询示例：

```sql
-- 按时间聚合某项目健康度趋势
SELECT
    date_trunc('day', completed_at) AS day,
    avg(health_score_snapshot)        AS avg_health
FROM reviews
WHERE project_id = $1 AND status = 'completed'
GROUP BY day
ORDER BY day;
```

> **说明**：原 `review_trends` 冗余表已移除。`health_score_snapshot` 建议作为 `reviews` 表的一个字段，保存该次审查时的评分快照，便于历史趋势还原。

### 4.3 Pydantic模型定义

```python
from pydantic import BaseModel, Field
from typing import Optional, List, Dict, Any
from datetime import datetime
from enum import Enum
import uuid

# 枚举类型
class ProjectStatus(str, Enum):
    ACTIVE = "active"
    INACTIVE = "inactive"
    ARCHIVED = "archived"

class ReviewStatus(str, Enum):
    PENDING = "pending"
    RUNNING = "running"
    COMPLETED = "completed"
    FAILED = "failed"

class Severity(str, Enum):
    CRITICAL = "critical"
    WARNING = "warning"
    SUGGESTION = "suggestion"
    NITPICK = "nitpick"

class FindingStatus(str, Enum):
    OPEN = "open"
    ACKNOWLEDGED = "acknowledged"
    FIXED = "fixed"

class TriggerType(str, Enum):
    MANUAL = "manual"
    SCHEDULED = "scheduled"
    WEBHOOK = "webhook"

# 项目模型
class ProjectBase(BaseModel):
    name: str = Field(..., min_length=1, max_length=255)
    path: str = Field(..., min_length=1, max_length=1024)
    description: Optional[str] = None
    language: Optional[str] = None
    framework: Optional[str] = None

class ProjectCreate(ProjectBase):
    pass

class ProjectUpdate(BaseModel):
    name: Optional[str] = None
    description: Optional[str] = None
    language: Optional[str] = None
    framework: Optional[str] = None
    is_active: Optional[bool] = None

class Project(ProjectBase):
    id: uuid.UUID
    git_remote: Optional[str] = None
    health_score: float = 0.0
    last_review_at: Optional[datetime] = None
    created_at: datetime
    updated_at: datetime
    is_active: bool = True
    
    class Config:
        from_attributes = True

# 审查模型
class ReviewBase(BaseModel):
    trigger_type: TriggerType
    review_type: str

class ReviewCreate(ReviewBase):
    project_id: uuid.UUID

class Review(ReviewBase):
    id: uuid.UUID
    project_id: uuid.UUID
    status: ReviewStatus
    started_at: Optional[datetime] = None
    completed_at: Optional[datetime] = None
    duration_seconds: Optional[int] = None
    health_score_snapshot: Optional[float] = None
    total_findings: int = 0
    critical_count: int = 0
    warning_count: int = 0
    suggestion_count: int = 0
    nitpick_count: int = 0
    summary: Optional[str] = None
    created_at: datetime
    
    class Config:
        from_attributes = True

# 发现模型
class FindingBase(BaseModel):
    agent_name: str
    category: str
    severity: Severity
    status: FindingStatus = FindingStatus.OPEN
    file_path: Optional[str] = None
    line_number: Optional[int] = None
    column_number: Optional[int] = None
    code_snippet: Optional[str] = None
    message: str
    description: Optional[str] = None
    suggestion: Optional[str] = None
    reference_url: Optional[str] = None
    is_auto_fixable: bool = False
    fix_suggestion: Optional[str] = None

class FindingCreate(FindingBase):
    review_id: uuid.UUID

class Finding(FindingBase):
    id: uuid.UUID
    review_id: uuid.UUID
    created_at: datetime
    
    class Config:
        from_attributes = True

# 配置模型
class ProjectConfigBase(BaseModel):
    config_key: str
    config_value: Dict[str, Any]
    description: Optional[str] = None

class ProjectConfigCreate(ProjectConfigBase):
    project_id: uuid.UUID

class ProjectConfig(ProjectConfigBase):
    id: uuid.UUID
    project_id: uuid.UUID
    created_at: datetime
    updated_at: datetime
    
    class Config:
        from_attributes = True

# 健康度模型
class HealthScore(BaseModel):
    overall: float = Field(..., ge=0, le=100)
    code_style: float = Field(..., ge=0, le=100)
    dependency: float = Field(..., ge=0, le=100)
    test_coverage: float = Field(..., ge=0, le=100)

# 说明：健康度仅基于可验证维度（安全/规范/依赖/测试），不包含架构、部署等主观维度
# 防止不可靠的评分污染整体健康度可信度
    test_coverage: float = Field(..., ge=0, le=100)
    
class ProjectHealth(Project):
    health: HealthScore
    recent_reviews: List[Review] = []
    top_issues: List[Finding] = []
```

### 5.3 主 Agent 编排设计（CrewAI Flows + Crews）

本系统采用 **Flows + Crews 双层架构**，这是 CrewAI 的新范式（2025/2026 年官方推荐最佳实践）：

```text
┌──────────────────────────────────────────────────────────────────────┐
│                    ReviewFlow（外层 Flow）                           │
│  确定性控制 · 状态管理 · 流程编排                                    │
│                                                                      │
│  @start  parse_pr()        → 解析 PR/diff，提取文件列表              │
│  @listen  analyze_files()  → 分析文件类型，决定参与 Agent            │
│  @listen  run_reviews()    → 创建 Crew 并行审查                      │
│  @listen  aggregate()      → 去重/合并/排序/健康度                   │
│  @listen  generate_report()→ 生成结构化报告                          │
│  @router  route_by_type()  → 根据审查类型分支                        │
└──────────────────────────────────────────────────────────────────────┘
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
┌────────────┐ ┌────────────┐ ┌────────────┐
│ SecurityCrew│ │ StyleCrew  │ │ DepCrew    │
│ 内层 Crew   │ │ 内层 Crew  │ │ 内层 Crew  │
│ Agent 自主  │ │ Agent 自主 │ │ Agent 自主 │
│ 工具调用    │ │ 工具调用   │ │ 工具调用   │
└────────────┘ └────────────┘ └────────────┘
```

**设计原则**：
- **外层 Flow**：用 Python 原生代码控制流程，状态用 Pydantic model 管理，确定性强、可调试
- **内层 Crew**：每个 Crew 包含一个专业 Agent，自主决定如何使用工具完成审查任务
- **状态驱动**：Flow 的每一步都是有状态的，可以中断/重试/持久化

```python
# === 外层 Flow（确定性控制 + 状态管理）===
from crewai.flow.flow import Flow, listen, start, router
from pydantic import BaseModel
from typing import List

class ReviewState(BaseModel):
    pr_url: str = ""
    diff_files: List[dict] = []
    agent_assignments: dict = {}  # {agent_name: [files]}
    review_results: dict = {}     # {agent_name: [findings]}
    final_report: str = ""
    status: str = "pending"

class ReviewFlow(Flow[ReviewState]):

    @start()
    def parse_pr(self):
        """解析 PR/diff，提取文件列表和变更行"""
        self.state.diff_files = parse_diff(self.state.pr_url)
        self.state.status = "parsed"

    @listen(parse_pr)
    def analyze_files(self):
        """分析文件类型，决定哪些 Agent 需要参与"""
        self.state.agent_assignments = decide_agents(self.state.diff_files)
        self.state.status = "assigned"

    @listen(analyze_files)
    def run_reviews(self):
        """并行运行多个 Crew 进行审查"""
        # 每个 Agent 对应一个 Crew，各自独立上下文
        crew_results = run_agent_crews(self.state.agent_assignments)
        self.state.review_results = crew_results
        self.state.status = "reviewed"

    @listen(run_reviews)
    def aggregate(self):
        """去重、合并、排序"""
        self.state.review_results = aggregate_findings(self.state.review_results)
        self.state.status = "aggregated"

    @listen(aggregate)
    def generate_report(self):
        """生成结构化审查报告"""
        self.state.final_report = build_report(self.state.review_results)
        self.state.status = "completed"

# === 内层 Crew（Agent 自主协作）===
from crewai import Agent, Task, Crew, Process

def run_agent_crews(assignments: dict) -> dict:
    """为每个 Agent 创建独立 Crew，运行审查任务"""
    results = {}
    for agent_name, files in assignments.items():
        # 每个 Agent 独立的 Crew，上下文隔离
        agent = create_agent(agent_name)  # 根据名称创建对应 Agent
        task = Task(
            description=f"审查以下文件: {files}",
            agent=agent,
            expected_output="结构化审查发现列表",
        )
        crew = Crew(
            agents=[agent],
            tasks=[task],
            process=Process.sequential,  # 单 Agent 用 sequential
            verbose=True,
        )
        result = crew.kickoff(inputs={"files": files})
        results[agent_name] = result
    return results
```

> **为什么用 Flows + Crews 而不是纯 hierarchical Crew？**
> 1. 纯 Crew 是黑盒：框架隐式决定任务分配和执行顺序，调试困难
> 2. Flow 是白盒：每一步都是确定性 Python 代码，状态可追踪、可断点调试
> 3. 这个场景外层要确定性（任务分解/聚合/报告），内层要自主性（各 Agent 独立审查），天然适合双层
> 4. 学习价值：掌握 CrewAI 的两种范式，面试时能讲清"何时用 Flow、何时用 Crew、何时结合"

### 5.4 WebSocket API（实时更新）

> **进度桥接设计（重要）**：审查任务跑在 worker（Celery 或后台任务）里，进度要实时推到浏览器，链路为：

## 8. 开发计划

### 8.0 模块优先级矩阵（成本 × 价值）

> 这是本系统的**核心决策记录**：按"实现成本"与"业务价值"对功能模块分档，指导开发顺序与范围裁剪。

| 档位 | 模块 / 能力 | 实现成本 | 价值 | 决策 |
|------|-------------|----------|------|------|
| **P0** | 基础框架（FastAPI + React + DB） | 中 | 极高 | 必做 |
| **P0** | 触发层（本地目录 / 代码粘贴 / 文件上传 / CLI） | 低 | 高 | 必做 |
| **P0** | 主Agent编排（CrewAI Flows + Crews 双层架构） | 中 | 极高 | 必做 |
| **P0** | 代码安全审查Agent（Semgrep + LLM） | 中 | 高 | 必做 |
| **P0** | 代码规范审查Agent（Ruff + LLM点评） | 低 | 中高 | 必做 |
| **P0** | 报告生成 + 前端结果展示 | 中 | 高 | 必做 |
| **P1** | 依赖审查Agent（pip-audit / npm audit） | 低 | 中 | 推荐做 |
| **P1** | 测试覆盖Agent（coverage.py + LLM建议） | 中 | 中 | 推荐做 |
| **P1** | WebSocket实时进度（含Celery桥接） | 中 | 中 | 推荐做 |
| **P1** | 结果聚合 / 健康度 / 统计 | 低 | 中 | 推荐做 |
| **P2** | 增量审查（diff行级，省token） | 中 | 高 | 视时间考虑 |
| **P2** | 性能分析Agent（AST模式 + LLM） | 中高 | 中 | 视时间考虑 |
| **P2** | Git审查Agent（提交规范/分支策略） | 中 | 中 | 视时间考虑 |
| **P2** | 自动修复（简单问题） | 中高 | 中 | 视时间考虑 |
| **✗ 摘出** | 架构审查Agent | 高 | 低（不可验证） | **不做** |
| **✗ 摘出** | 部署审查Agent | 中 | 低 | **不做** |
| **✗ 简化** | 全套监控栈（Prom/Grafana/Loki/Jaeger） | 高 | 低 | **移除，改Langfuse+structlog** |

**开发原则**：先做 P0（MVP + 核心审查），再做 P1（增强审查与体验），P2 视进度裁剪。宁可交付"完整可用的核心系统"，也不做"每模块半成品"。
