# 多Agent协作代码审查系统 - 开发规划

## 1. 项目概述

### 1.1 项目目标
构建一个**多 Agent 协作代码审查系统**，支持多种触发方式（本地目录/代码粘贴/文件上传/CLI/GitHub Webhook），以 PR/diff 增量审查为核心场景，支持：
- 多 Agent 并行审查（安全/规范/依赖/测试覆盖等）
- 主 Agent 编排（CrewAI Flows + Crews 双层架构：外层确定性控制 + 内层Agent自主协作）
- 结构化审查报告与实时进度展示
- 可验证维度的健康度与统计趋势

### 1.2 核心价值
1. **学习价值**：覆盖多Agent协作、任务调度、LLM应用等核心概念
2. **实用价值**：可用于管理个人/团队的多个项目
3. **面试亮点**：完整的项目经历，可展示技术深度

### 1.3 成功标准
- ✅ 支持多种触发方式（本地目录/代码粘贴/文件上传/CLI）
- ✅ 实现核心审查 Agent：安全(P0)、规范(P0)、依赖(P1)、测试覆盖(P1)
- ✅ 生成结构化审查报告
- ✅ 提供可视化仪表盘与实时进度
- ✅ 支持Python/JavaScript/TypeScript语言

> 架构审查/部署审查已摘出，完整优先级分档见 `技术架构设计.md` 8.0 节。

## 10. 可实施开发计划（详细版）

> 本章节基于前面的阶段规划，提供更详细的"可立即执行"的开发步骤，包含检查点和风险预警。

### 10.1 开发原则

1. **每阶段结束必须有可演示的东西**：不是"代码写了"，而是"能看到效果"
2. **先跑通再优化**：不要一开始就追求完美架构
3. **锁版本**：CrewAI、FastAPI、SQLAlchemy等核心依赖必须锁版本
4. **框架与业务分层**：CrewAI 的 Agent/Task/Flow 只做"调用层"，核心逻辑（工具调用、结果解析、校验）放在独立 Service 层

### 10.2 第1周：MVP（每日检查点）

| 日 | 任务 | 验收标准（必须达到） |
|----|------|---------------------|
| Day 1 | 项目初始化 | `docker-compose up` 成功，前后端可访问 |
| Day 2 | 后端基础 | `/docs` 可访问，数据库连接成功 |
| Day 3 | 前端基础 | 页面可访问，路由可切换 |
| Day 4 | API开发 | 项目CRUD接口可调用，数据可入库 |
| Day 5 | 联调测试 | 前端可创建/查看项目，无报错 |

**风险预警**：Docker 环境配置是第1周最大坑，Day 1 必须解决。

### 10.3 第3周：CrewAI + 安全审查（每日检查点）

| 日 | 任务 | 验收标准（必须达到） |
|----|------|---------------------|
| Day 1 | CrewAI环境 | `crewai` 可导入，Flows/Crews Hello World 可运行 |
| Day 2 | ReviewFlow | Flow 可执行，状态可追踪，日志可见 |
| Day 3 | 安全Agent | Agent 可调用 Semgrep，输出可解析 |
| Day 4 | Flow集成 | 端到端流程可运行：输入文件 → 安全审查 → 结果入库 |
| Day 5 | 报告+联调 | 前端可触发审查，结果可展示，报告可下载 |

**风险预警**：
- CrewAI API 变动：Day 1 必须锁版本（`crewai==0.x.y`）
- 结构化输出不稳定：Day 3 必须加 Pydantic schema 校验
- Semgrep 安装/运行：Day 3 必须验证 `semgrep` 命令可用

### 10.4 每周结束必须完成的事

1. **代码可运行**：不是"写了代码"，而是"docker-compose up 后能看到效果"
2. **测试可跑**：至少核心流程的集成测试可跑通
3. **文档可更新**：更新 README、API文档、学习笔记
4. **风险可记录**：记录本周遇到的问题和解决方案

### 10.5 范围裁剪预案

如果某周进度落后，按以下优先级裁剪：

| 优先级 | 功能 | 裁剪后果 |
|--------|------|----------|
| 不可裁剪 | 项目CRUD + 审查流程 + 结果展示 | 没有这些，项目不成立 |
| 可延后 | WebSocket实时进度 | 改为轮询，体验差但功能完整 |
| 可延后 | 健康度计算 + 统计趋势 | 报告中不展示评分，手动查看 |
| 可砍掉 | 性能分析Agent（P2）| 少一个审查维度，不影响核心 |
| 可砍掉 | Git审查Agent（P2）| 少一个审查维度，不影响核心 |
