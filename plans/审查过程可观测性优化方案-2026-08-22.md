# 审查过程可观测性优化方案（讨论稿 v1）

**创建日期**：2026-08-22
**状态**：讨论稿（尚未实现）
**目标**：让用户对审查过程"清清楚楚感知每一步"——不只看到最终问题列表，而是看到整个任务流：每一步做了什么、输入什么、产出什么、耗时多少、跳过了什么。**这是一个学习工具**，不是状态面板。

---

## 一、现状问题

- `progress_emitter` 是**内存级**事件总线：事件只存内存，审查结束、订阅者断开后即清理，**不持久化**。
- 现有事件类型太少：只有 `review_started` / `flow_node_started/completed` / `agent_started/completed` / `review_completed/failed`，且 data 里只有基础信息。
- 前端 `ReviewProgress` 只在审查进行时实时展示（WS），审查完成后无法回看过程。
- `Review` 表只有最终结果（findings / summary / health / duration），无过程步骤。

---

## 二、核心设计：`review_steps` 表（持久化每一步）

新增 SQLAlchemy 模型 `ReviewStep`，表 `review_steps`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str(uuid) | 主键 |
| `review_id` | FK → reviews.id | 关联审查 |
| `sequence` | int | 步骤序号（时间线排序） |
| `phase` | str | `outer_flow` / `inner_crew` / `tool` / `llm` |
| `node_type` | str | parse_project / run_*_crew / aggregate / generate_report / agent_think / tool_call / llm_call / skip_agent ... |
| `agent_name` | str | 涉及 Agent（security/code_style/...） |
| `status` | str | running / completed / skipped / failed |
| `action_text` | str | **中文描述"这一步做了什么"**（学习核心） |
| `input_summary` | text | 输入摘要（扫描 N 文件、输入 JSON 大小等） |
| `output_summary` | text | 输出摘要（产出 M 条 findings、tokens 等） |
| `started_at` | datetime | 开始时间 |
| `ended_at` | datetime | 结束时间 |
| `duration_ms` | int | 耗时（毫秒） |
| `detail` | JSON | 额外详情（LLM tokens、工具参数、异常信息、跳过原因） |

随 review 级联删除。

## 三、每一步记录什么（学习粒度）

### 3.1 外层 Flow（4 类节点）

| 节点 | action_text 示例 |
|------|------------------|
| `parse_project` | "读取项目目录，收集 10 个代码文件，判断语言为 Python，按审查类型 security 确定参与 Agent：security" |
| `run_*_crew` | "启动安全审查专家（CrewAI Crew），专家开始自主执行" |
| `aggregate` | "合并各 Agent 发现，去重 23 → 17 条，统计严重度：critical 2 / warning 8 / suggestion 7" |
| `generate_report` | "生成总结摘要，计算健康分 54.0" |

### 3.2 内层 Crew（Agent 完整执行链）

- Agent 启动：角色「资深代码安全审查专家」、goal、backstory 摘要
- **思考**：Agent 决定调用工具的思考过程（Thought）
- **工具调用**：`security_review_scan` → 内部动作 → 返回 N 条 findings
  - 子步骤：Semgrep 各规则集（扫描文件数、耗时、发现数）→ LLM 分析各文件（tokens、耗时）
- **LLM 收尾**：审阅工具结果 → 整理为结构化输出

### 3.3 工具 / LLM 细节（最细粒度）

- Semgrep：每个规则集、扫描文件数、耗时、异常
- LLM：模型、每次调用的文件、prompt/completion tokens、耗时
- 数据库：findings 入库条数

### 3.4 跳过 / 异常

- `skip_agent`：review_type 过滤跳过了哪些 Agent（如 security 类型跳过 dependency/test_coverage/...）
- 工具异常：Semgrep 失败、LLM 失败、降级路径（都记录 detail）

## 四、数据来源与改造点

1. **持久化**：`progress_emitter.emit()` 增加写库（现有实时 WS 推送不变）。
2. **补发详细事件**（在 review_flow / crew_factory / agents 里补发）：
   - `tool_call_started/completed`：工具名、输入、输出摘要
   - `llm_call`：模型、tokens、耗时
   - `aggregate`：去重前后数量、严重度分布
   - `skip_agent`：被跳过的 Agent 及原因
   - `parse_project`：收集文件数、语言、参与 Agent
   - `report`：摘要文本、健康分
3. **工具/LLM 内部埋点**：Semgrep 每个规则集、LLM 每次调用都发步骤事件。

---

## 五、前端展示（ReviewDetail.tsx 新增「执行流程」面板）

1. **时间线总览**：外层 Flow 节点 + 内层 Crew 卡片，每步状态 ✅/⏳/⏹、耗时、findings 数。
2. **点击展开**：每步展开看 `action_text` + 输入/输出摘要 + 工具/LLM 子步骤。
3. **流程图联动**：复用 ReviewProgress 的 Flow 图，点击节点定位时间线。
4. **执行报告**：审查完成后生成结构化"流水账"（复制即学习）。

新增 API：`GET /api/v1/reviews/{id}/steps` 返回完整步骤时间线。
